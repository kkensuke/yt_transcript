# Homebrew releases

The Homebrew distribution uses two repositories with separate responsibilities:

- `kkensuke/yt_transcript` owns source code, versions, tags, tests, and GitHub Releases.
- `kkensuke/homebrew-tap` owns the generated `Formula/yt-transcript.rb` consumed by Homebrew.

Users install both the CLI and browser app with one command:

```bash
brew install kkensuke/tap/yt-transcript
```

The installed command is `yt-transcript`; use its `web` subcommand to start the browser app.

## Packaging design

The Formula builds the tagged source archive in a private Python virtual environment. Runtime and Web dependencies are selected from `uv.lock`, downloaded as SHA-256-pinned source resources, and installed without relying on the unrelated PyPI project that currently owns the `yt-transcript` distribution name.

The Formula uses Homebrew's `python@3.14` and `pydantic` packages. The latter supplies the compiled `pydantic-core` dependency for supported Homebrew platforms. All remaining runtime resources, including `yt-dlp`, FastAPI, and Uvicorn, are generated by `scripts/render_homebrew_formula.py` from the locked dependency graph. Development-only and Windows-only packages are excluded.

This design provides:

- a stable `vMAJOR.MINOR.PATCH` source URL and checksum;
- explicit, reproducible runtime inputs with every declared resource checksum verified by Homebrew;
- the same `yt-transcript` command on Apple Silicon, Intel macOS, and Linuxbrew;
- a Formula test that checks the version, Web command help, and a live `/healthz` response.

## One-time Tap setup

The Tap repository and scoped release credential must exist before pushing the first release tag.

1. Create the public `kkensuke/homebrew-tap` repository. Homebrew's recommended bootstrap command is:

   ```bash
   brew tap-new kkensuke/homebrew-tap
   gh repo create kkensuke/homebrew-tap \
     --public \
     --source "$(brew --repository kkensuke/tap)" \
     --push
   ```

2. Create a fine-grained GitHub personal access token limited to `kkensuke/homebrew-tap` with repository **Contents: Read and write** permission. It does not need access to other repositories.

3. In `kkensuke/yt_transcript`, create a `release` environment and add the token as the `HOMEBREW_TAP_TOKEN` environment secret. Optional required reviewers on this environment provide a manual release gate.

4. Keep the default Tap branch named `main`. The release workflow writes only `Formula/yt-transcript.rb` and stages only that path.

The workflow fails before publishing if the Tap or secret is missing. After correcting setup, rerun the failed workflow for the existing tag.

## Publishing a release

1. Update both version declarations and the lock file:

   ```bash
   uv lock
   uv run --all-extras pytest
   ```

2. Merge the release commit to `main`.

3. Create and push a signed stable tag that matches the project version:

   ```bash
   git tag -s v0.4.0 -m "yt-transcript 0.4.0"
   git push origin v0.4.0
   ```

The release workflow verifies that the tagged commit is on `main`, confirms both package version declarations, runs lint and tests, builds the wheel and source distribution, creates the GitHub Release, hashes the GitHub tag archive, renders the Formula, and commits it to the Tap.

## Verifying the Tap

After the Tap update completes, test a source build before announcing the release:

```bash
brew update
brew install --build-from-source kkensuke/tap/yt-transcript
brew test kkensuke/tap/yt-transcript
brew audit --strict kkensuke/tap/yt-transcript

yt-transcript --version
yt-transcript web
```

Upgrades then follow the normal Homebrew path:

```bash
brew upgrade yt-transcript
```

## Dependency updates

Run `uv lock --upgrade-package PACKAGE` and release a patch version when a runtime resource changes. This is especially important for `yt-dlp`, because YouTube changes can require rapid upstream updates. The Formula renderer fails rather than emitting an unpinned dependency or a package without a source distribution.

Homebrew Core can be considered later, after the project has a track record of stable tagged releases and meets Core's notability and maintenance requirements. Until then, the upstream Tap keeps release timing under project control.
